Technical plan · before implementation

Temporal agent evaluation

Build one versioned tool-data substrate that lets an agent see only what was available at a chosen time, then use it first as an optional TradingAgents backtest mode and later as a standalone product.

Recommendation

Shared core + repo adapter. Do not fork the existing agent graph or start with a whole-web crawler.

Existing repo

Keep the analysis system

The LangGraph pipeline, analyst roles, prompts, structured decisions, reports, and existing vendor routing stay in place.

trading_graph.py · dataflows/interface.py · agents/

New capability

Add a time boundary

A capture/replay layer records tool inputs and source responses, selects only versions available at virtual time T, and emits an auditable trace.

Product seam

Make the core generic

The core is tool-agnostic. Trading data, web research, internal APIs, code tools, and browser actions become connectors rather than product-specific assumptions.

The boundary that avoids a rewrite

Current tool names remain stable; their data source becomes selectable

The graph stays the decision engine. The new layer sits at the tool/data boundary. The one direct-call exception—StockTwits and Reddit prefetch in the sentiment analyst—moves behind the same source adapter so it can be captured and replayed.

Common agent calls worth normalizing first

A small universal “tool tape” beats an internet clone

Research web

search, open URL, read/extract, click, download

Structured data

HTTP/API request, SQL query, data-vendor lookup

Knowledge work

search docs/Slack/email, write a cited research note

Software work

search repo, read file, run test, apply patch

Actions

submit order, create ticket, send message, deploy—always through a separately modeled stateful simulator or approved live connector.

One core, two surfaces

Build once; package twice

TradingAgents integration

first adopter
  • Optional live, capture, and replay data modes.
  • Historical runs produce reports plus evidence citations and decision traces.
  • Scenario runner compares decisions; execution/portfolio simulation is a later module.
  • Preserves default live behavior and existing tool names.

General product

commercializable
  • SDK/proxy captures any JSON tool call plus browser/API evidence.
  • Private, versioned corpus with virtual-time retrieval and cryptographic provenance.
  • Evaluation runner integrates with existing trace platforms instead of replacing them.
  • Self-hosted mode targets regulated research, finance, security, and enterprise agents.

Non-goals for v1

  • “Archive the whole web.” Start with explicit sources and tool calls.
  • Live broker credentials or real capital.
  • Replacing LangSmith, browser benchmarks, or web archives.
  • Claiming exact historical availability when only an archive capture exists.
