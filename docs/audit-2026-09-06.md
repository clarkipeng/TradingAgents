# Deep audit - 2026-09-06

Three-track audit (data layer, research path, ops/portfolio) with measurements taken against the production store and tapes.
Findings ranked: replay-trust bugs first, then money-path correctness, then cost/latency, then hygiene.
Chat summary delivered same day; this file is the durable copy.

## Track A - trust: sealed days are not actually replayable today

1. Research tape unreachable from the seal (portfolio_run.py:539 vs :418; langchain.py:368).
Workers tape under `run:research:TICKER`, the seal stores the bare `run` id, and production writes `scenario_id=None` on llm_calls - replay lookups match zero rows.
2. Capture/replay prompt divergence (trading_graph.py:436-444).
Production capture resolves instrument context live; replay takes the historical branch and appends a "Historical simulation" sentence - exact-match prompt verification can never pass.
3. The market analyst's "source of truth" tool is untaped (market_data_validation_tools.py:25).
`build_verified_market_snapshot` bypasses the gateway entirely: zero traces exist for it, and at replay it would read live yfinance (or refuse on staleness).
Each of the three is independently sufficient to break replay. The golden full-trace replay test was never exercised against a production day, which is why all three survived.

## Track B - money-path correctness

4. One transient quote error kills the whole day (portfolio_run.py:320): the quote loop is the only stage without per-item failure isolation; a vendor hiccup on ticker 17/30 discards two hours and all research spend.
5. `_last_close` returns the oldest row for descending CSVs and never checks the date (portfolio_run.py:578) - one config change (alpha_vantage first) would price every fill ~a week stale, silently. Also uses raw close, not adjusted.
6. Stale-claim window (3600s) is half the day deadline (7200s) - a manual re-run an hour into a healthy day forcibly takes over the claim: two processes trade the same day.
7. Budget exhaustion at the CIO masquerades as "proposal rejected (AttributeError)" and seals a hold-the-book day; and briefs are unfiltered while ratings are quote-filtered, so the CIO can propose an out-of-universe ticker and get the whole plan rejected.
8. Buy sizing ignores fees/slippage (portfolio_run.py:616 + simulation.py:89): fully-invested plans can overdraw on the last buys, which are silently skipped; the new band skipping sells makes it worse. Simulator also lacks Decimal quantization (28-digit tails compound day over day), depends on mutable global decimal context, and applies asymmetric slippage.
9. SIGTERM handling: fly kill_timeout=300s vs jobs up to 9000s; supervisor never forwards SIGTERM to the child, so a deploy in the 17:45-20:00 window SIGKILLs a mid-write day. Deadline path also hangs at exit: ThreadPoolExecutor's atexit joins hung workers despite shutdown(wait=False).
10. Silent failure everywhere: temporal-portfolio-run exits 0 on every failure kind; supervisor logs exit=0 for unsealed days; no alerting.
11. Discovery queries the wrong UTC day every day (cloud_supervisor discovery job passes no --date; 18:30 LA is past UTC midnight) - the trading day's headlines are never captured.
12. sync_store_down.sh greps for the removed 7-slot backup names - the offsite pull has failed quietly since the single-slot change.
13. Trader's poller child runs unbudgeted macro polling (macro defaults on; MEDIA_COLLECTION_ENABLED pause switch doesn't gate it), and inherits the collector's alert webhook + health port.
14. Retry storm: any post-cycle failure tears down the poller daemon, backoff resets after each successful cycle, so a persistent post-cycle bug re-runs the full provider sweep every ~5s with no budget on news providers.

## Track C - cost and latency (measured)

15. `documents(cluster_key)` unindexed: every search does ~limit full-table scans (body-laden rows) for sibling lookups - plausibly the dominant I/O of every temporal_search. Fix: one index.
16. `evidence(available_at)` unindexed: the corpus-hash freshness probe full-scans 306k wide rows on every search/seal/verify. Fix: covering index (available_at, evidence_id).
17. `get_stock_data` never uses the existing 5-year on-disk OHLCV cache (~46s/call, ~1350s/day). `get_indicators` reloads the CSV per indicator. Same-run duplicate `.info` scrape costs another ~800s/day.
18. ReAct loop re-sends tool results 2.01x (measured): ~750k input tokens/day are literal re-sends. Truncate/stub consumed ToolMessages or batch indicator requests.
19. Tape overhead: 4 sqlite connects per LLM call incl. two gratuitous `get_llm_call` re-reads nobody consumes; `x_posts` writes ~30 exclusive transactions per call (measured 30.3); trace sequence via SELECT MAX under BEGIN IMMEDIATE serializes all 4 workers.
20. corpus_hash digest builds a ~16MB canonical-JSON string per recompute under a lock, and the run's own tapes invalidate it (documents-level fix exists; evidence-level didn't get it). Key it like eligible_index or hash incrementally.
21. media_posts_asof JSON-parses every row in the window per call (no usable index; json_extract predicates). Fix: partial index + generated columns.
22. corpus_overview: pointless evidence join + O(rows x domains) Python counting; should be one GROUP BY.
23. evidence_fts stores a full second copy of every document and is never read in production; same bytes stored three times (inline + artifact + fts). Drop it: large disk + ingest-latency win.
24. _refresh_document_clusters is O(corpus) even for one target (enumerates every candidate pair, inside the publication transaction; per-500-row batch during drains). Also: ubiquitous_cutoff scales with corpus size, so cluster assignments are not stable as the corpus grows - a determinism smell.
25. Connection churn: every op opens/closes a connection; last-close triggers WAL checkpoints; active_generation_id called 3x per search. Thread-local persistent connections.
26. Capture/import paths hold the store flock across vendor HTTP calls (tradingagents.py:138, cli gdelt import); reindex CLI holds it across the whole generational rebuild it was designed to avoid.
27. Prompt ordering: per-ticker instrument context sits at ~token 140, ahead of ~1500 static tokens - defeats cross-ticker prefix caching (~180k tokens/day at full rate).
28. Memory-log machinery is dead weight in analysts_only (parsed twice per ticker, consumed by a node that isn't in the graph; stray pending entries can trigger untaped LLM calls).

## Track D - hygiene

29. store.search: 120 lines of unreachable duplicated retrieval code (marked unreachable) that has already drifted - a trap.
30. tool_traces/search_traces each maintain an index byte-identical to their UNIQUE constraint (double B-tree per insert).
31. llm_calls/tool_traces/search_traces grow forever, no retention; llm_calls double-stores payloads inline and as artifacts.
32. Python floor: pyproject says >=3.10 but the deadline path's bare TimeoutError only works on >=3.11 (prod pins 3.12).
33. Supervisor fired-set pruning triggers at len>1000 (~200 days) - effectively never.
